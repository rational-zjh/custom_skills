# rutocn（俄文转中文）

把用户提供的俄文文件或整个项目转换为中文，按规则输出到 `<原名称>-cn` 文件夹；翻译完成后必须询问是否生成报告与演示文稿。

## 适用范围

- 用户要求“俄文转中文”“把项目/脚本转成中文”“convert ru to cn”“rutocn”
- 典型输入：`.ngscript`、`.engee` 脚本项目，以及 `.txt/.md/.json/.csv/.xml/.yaml/.ipynb` 等文本文件
- 仅在用户明确请求时执行，不要自动触发

## 强制确认（不可跳过）

完成翻译和输出文件夹后，**暂停并同时询问**下面两个问题，未得到答复前不得生成报告或 PPT：

1. 是否根据整个文件的内容生成一份 `.docx` 报告？
2. 是否根据整个文件的内容生成一份 `.pptx` 演示文稿？

用户拒绝则跳过，不要反复追问；用户已明确指定过的选项直接沿用，不要重复提问。

## 处理流程

### 1. 确定输出位置

1. 只读附件目录中的文件先复制到工作区可编辑目录，再处理
2. 原名称：输入是文件夹或项目目录 → 用该目录名；输入是单个文件 → 用去掉扩展名的文件名
3. 在工作区创建 `<原名称>-cn` 文件夹，保留原始子目录结构
4. 不覆盖、不修改任何原始文件

### 2. 翻译规则

- 所有自然语言俄文（西里尔字母 `\u0400-\u04FF`）译为简体中文
- 英文内容原样保留，不改动
- 保持原样：代码、标识符、变量名、函数名、路径、文件名、键名、URL、邮箱、数字、日期、格式符号、文件中已有的中文
- 需要翻译：注释、文档字符串，以及面向用户的字符串（绘图标题、坐标轴标签、界面提示、说明文字）
- 若字符串参与程序逻辑（路径、枚举值、字典键、正则、命令参数、匹配条件），保持原样，并在交付说明中列出
- 术语、人名、地名采用通用译名，全文保持一致

### 3. 单位转换（俄制单位 → 英文单位）

已是英文或国际符号的单位保持不变，只替换俄制写法。数字与单位之间的空格沿用原文。

| 俄文单位 | 英文输出 | 俄文单位 | 英文输出 |
| --- | --- | --- | --- |
| мм | mm | кг | kg |
| см | cm | г | g |
| м | m | т | t |
| км | km | с | s |
| м² | m² | мин | min |
| м³ | m³ | ч | h |
| л | L | В | V |
| мл | mL | кВ | kV |
| А | A | Вт | W |
| кВт | kW | Гц | Hz |
| кГц | kHz | МГц | MHz |
| Ом | Ω | кОм | kΩ |
| Па | Pa | кПа | kPa |
| МПа | MPa | Н | N |
| Н·м | N·m | Дж | J |
| кДж | kJ | рад | rad |
| об/мин | rpm | м/с | m/s |
| км/ч | km/h | К | K |
| °C | °C | % | % |

- 单词形式同样转换：`метр` → `m`、`килограмм` → `kg`、`секунда` → `s`、`градус` → `°`
- 复合单位逐项替换，如 `м/с²` → `m/s²`、`Н·м` → `N·m`
- 单位出现在变量名、枚举、配置键中时保持原样，不做转换

### 4. 文件命名与写入

- `.engee`、`.ngscript`：在扩展名前加 `-cn`，如 `main.ngscript` → `main-cn.ngscript`、`model.engee` → `model-cn.engee`
- 其他扩展名：文件名完全不变
- 文本文件：把翻译后的完整内容写入输出目录中的文件
- `.ipynb`：保持 JSON 合法可解析，只翻译 markdown 文本、代码注释和用户可见字符串
- `.docx/.pptx/.xlsx/.pdf` 等二进制文档：调用对应 office 技能读取并翻译文本后另存为同名文件；无法可靠改写时原样复制，并在交付说明中标注“未翻译”
- 图片：不做 OCR、不改图片内容，按原名原样复制到输出目录

### 5. 自查（交付前必做）

1. 输出文件夹名称、文件命名、目录结构完全符合规则
2. 无残留俄文（有意保留的代码标识符和逻辑字符串除外）
3. 英文内容与原文一致，未被误改或误删
4. 单位已转为英文写法，没有中俄单位混用
5. `.ipynb` 的 JSON 可解析，脚本语法结构未被破坏
6. 原始文件未被修改

### 6. 生成 .docx 报告（仅在用户确认后）

报告内容基于整个文件的内容撰写，推荐章节：

1. 概述：2~3 句概括主题、性质与结论
2. 背景：项目语境、目标、上下游关系
3. 模块与结构：按逻辑拆分模块，逐条提炼关键信息与数据
4. 关键流程与数据：主流程、输入输出、参数与依赖
5. 分析：归纳、对比、风险与限制
6. 输出与结论：明确结论、交付物清单
7. 后续建议：可执行的下一步

没有对应内容的章节可省略或合并，不要硬凑空话。使用 docx 技能生成规整的中文 Word 文档，保存到输出文件夹。

### 7. 生成 .pptx 演示（仅在用户确认后）

基于整个文件的内容，按“封面 → 概述 → 背景 → 模块 → 流程与数据 → 分析 → 输出 → 结论”组织页面，页数按内容量控制。

- 每页必须写详细演讲者备注：讲稿要点、过渡句、预计提问与回答要点
- 文字精简，避免整段粘贴报告
- 使用 pptx 技能生成，保存到输出文件夹

## 交付说明

- 给出输出文件夹路径与文件清单
- 说明图片未处理、逻辑字符串保留、未翻译文件（如有）
- 说明报告与 PPT 是否生成

## 注意

- 不编造原文中不存在的数据或结论
- 除保留的代码与英文单位外，全部输出使用简体中文
- 不泄露超出本次任务范围的隐私或敏感信息
